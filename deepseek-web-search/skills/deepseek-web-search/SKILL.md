# DeepSeek Web Search

本技能提供两个 MCP 工具：`search`（联网搜索）与 `fetch`（网页正文抓取）。它们只读、无副作用，适合作为信息获取的第一入口。在带命名空间的宿主中，工具可能显示为 `mcp__deepseek_web_search__search` 和 `mcp__deepseek_web_search__fetch`；参数与语义不变。

## 适用判断

优先使用：

- 问题涉及训练数据之后发生的事件、发布、价格、版本、政策或人物动态。
- 需要核实事实、寻找一手来源、官方文档或多个独立来源。
- 已经拿到具体链接，需要阅读正文而不是搜索摘要。
- 需要用 `site:`、`lang:`、`after:`、`before:` 精确缩小范围。

不要使用：

- 本地文件、代码仓库、数据库等本地信息；改用文件与终端工具。
- 登录后、付费墙、验证码或需要点击/填表的页面；改用浏览器自动化。
- 大规模批量抓取；会有 QPS 与计费限制。
- 稳定常识或已有可靠答案的问题；直接回答，避免无效调用。

## 工具契约

### `search`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 1–128 字符，支持检索运算符 |
| `count` | integer | 否 | 1–50，默认 10；调研通常取 3–10 |
| `ori_question` | string | 否 | 1–128 字符，用户原始问题，用于改善意图理解 |
| `localization` | string | 否 | IP 地址，用于本地化结果偏好 |
| `need_content` | boolean | 否 | 默认 false；为 true 时附带页面正文（服务端会截断） |

返回一个 JSON 文本，结构为 `{"results":[...]}`。每个结果包含：

| 字段 | 含义 |
|---|---|
| `title` | 标题 |
| `url` | 结果链接 |
| `snippet` | 短摘要，通常 100–200 字符 |
| `summary` | 长摘要，通常 600–800 字符 |
| `content` | 页面正文；`need_content=false` 或正文缺失时为空，服务端默认截断到约 2 万字符 |
| `site_name` | 站点名，可能为 null |
| `site_icon` | 站点图标 URL，可能为 null |
| `date` | 发布时间，UTC RFC 3339，可能为 null |
| `rerank_score` | 0–3；≥1.5 通常表示高相关 |
| `authority` | 0–4；-1 表示未知；≥3 通常表示高权威 |

### `fetch`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `url` | string | 是 | 绝对 HTTP(S) URL，不含用户名/密码，最长 8192 字符 |

返回 `# 标题` 加 Markdown 正文；标题缺失时使用 URL。正文默认截断到约 20 万字符，截断处会附带省略标记。

### 错误语义

工具失败时返回 `isError: true` 和可读错误文本，不会伪造结果：

- 401：API Key 缺失或无效，检查插件配置。
- 402：账户余额不足。
- 403：抓取被安全策略拦截。
- 404：目标页面无法获得可用正文。
- 408/425/429/5xx：服务端会自动重试（默认最多 3 次，带退避）。
- 400：参数不合法，修正后重试；不要原样重复。

## 查询运算符

| 运算符 | 作用 | 示例 |
|---|---|---|
| `site:` | 限定站点，多个站点用 `OR` | `site:github.com OR site:huggingface.co` |
| `-site:` | 排除站点 | `-site:example.com` |
| `"短语"` | 精确短语 | `"Mixture of Experts"` |
| `-词` / `-"短语"` | 排除包含该词/短语的页面 | `-招聘 -"广告"` |
| `lang:zh,en` | 限定语言，逗号分隔 | `lang:zh,en` |
| `after:YYYY[-MM[-DD]]` | 限定发布时间下限 | `after:2026-01-01` |
| `before:YYYY[-MM[-DD]]` | 限定发布时间上限 | `before:2026-06-01` |

运算符可与普通关键词组合。检索语法不会扩展到 `fetch`。

## 标准流程

### 1. 时效性问题

1. `search` 使用明确主题，加入 `after:` 限定时间窗口，`count` 取 5–10。
2. 优先选择 `rerank_score ≥ 1.5` 且 `authority ≥ 3` 的结果。
3. 只对将要引用的 1–2 个页面调用 `fetch`。
4. 最终答复给出结论、日期与来源链接；不同来源冲突时并列说明。

### 2. 查找官方文档或一手来源

1. 使用 `site:` 限定官方域名，配合 `lang:`。
2. 从结果中选择最接近主题的 URL。
3. 用 `fetch` 读取正文；若正文被截断，优先阅读与问题直接相关的段落。
4. 引用官方页面，而不是搜索结果摘要。

### 3. 已知链接的正文读取

1. 直接调用 `fetch`。
2. 失败时按错误语义处理：404 不再重试同一 URL，改用搜索结果中的 `summary` 或换一个来源。
3. 不要把 Markdown 正文原样倾倒给用户；提炼与问题相关的信息。

### 4. 事实核查

1. 用两种不同表述各搜索一次，或限定两个独立来源。
2. 至少一个来源为高权威站点；注意发布日期是否覆盖被核查的时间点。
3. 仅当来源一致时给出确定结论；否则说明证据不足或存在分歧。

## 生产级操作规范

1. **先搜后取，按需取正文。** 默认 `need_content=false`，只为最终引用的页面调用 `fetch`。这能显著降低延迟、上下文占用和费用。
2. **查询先宽后窄。** 结果为空或偏离主题时，移除过于严格的运算符再试一次；不要连续重复同一查询。
3. **短查询补充 `ori_question`。** 当 `query` 只有关键词或来自多轮对话时，传入用户原问题以改善检索意图。
4. **控制结果数量。** `count` 通常取 3–10；只有需要广泛扫盘时才提高到 20–50。
5. **时间优先。** 对“最新/今天/最近”类问题，必须加 `after:`，并核对结果 `date`。
6. **信源分级。** 官方文档、监管机构、主流媒体优先；论坛、聚合站和自媒体仅作线索。`authority` 为 -1 时自行判断。
7. **引用不得编造。** 只使用工具返回的 `url`；引用格式为 `[标题](URL)`，必要时附发布日期。摘要与正文要区分来源。
8. **空结果要如实说明。** 一次放宽重试后仍为空，告知用户未找到，不要用常识补写“搜索结果”。
9. **不要重试不可恢复错误。** 401/402/403/404 需先修正配置、余额、策略或更换 URL；408/429/5xx 已由服务端自动重试。
10. **遵守账户限制。** 每账户约 5 QPS；计费按成功请求约 ¥5/1000 次，`count` 不影响单价。避免循环搜索同一主题。
11. **保护敏感信息。** 不把密钥、Cookie、内网地址放进 `query` 或 `url`；`fetch` 不接受带凭据的 URL。
12. **处理截断。** 见到 `[truncated: ...]` 时，只基于已有内容作答，或改用 `fetch` 获取更长正文；不要臆测缺失部分。

## 调用示例

时效性搜索：

```json
{
  "query": "DeepSeek 新模型发布 after:2026-01-01",
  "count": 5,
  "ori_question": "DeepSeek 最近发布了什么新模型？"
}
```

限定官方文档：

```json
{
  "query": "search API site:api-docs.deepseek.com lang:zh",
  "count": 5
}
```

读取指定页面：

```json
{
  "url": "https://api-docs.deepseek.com/zh-cn/guides/search/"
}
```

## 最终答复检查清单

- 结论是否直接回答了用户问题，而不是罗列搜索结果？
- 每个关键事实是否有可点击的真实来源？
- 是否标注了发布日期，避免把旧闻当新闻？
- 是否区分了搜索摘要与抓取正文？
- 是否存在未说明的截断、冲突或证据不足？
- 是否避免了不必要的额外搜索与抓取调用？
